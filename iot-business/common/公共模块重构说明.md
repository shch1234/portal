# 公共模块重构说明

## 重构目标

1. **将班次处理提取为公共模块的一部分**：班次查询功能作为业务公共模块的一部分，未来可以扩展其他公共功能
2. **通过接口实现模块间解耦**：各业务模块通过接口调用，不直接依赖具体实现类

## 重构内容

### 1. 创建公共模块结构

```
iot-business/
  common/                          # 业务公共模块
    common-api/                     # 公共API接口层
      - ShiftQueryApi.java         # 班次查询接口
    common-domain/                  # 公共领域模型层
      - ShiftInfoVO.java           # 班次信息VO
```

### 2. 定义公共接口

**`ShiftQueryApi`** - 班次查询API接口
- `getDeviceCurrentShift()` - 获取指定设备的当前班次
- `getFactoryCurrentShift()` - 获取工厂/车间的当前班次（从代表性设备获取）

**设计原则**：
- 接口定义在 `common-api` 模块中
- 各业务模块只依赖接口，不依赖实现
- 实现类可以放在任何模块中（当前在 device-mgmt 模块）

### 3. 实现类位置

**`ShiftQueryApiImpl`** - 实现类
- 位置：`device-mgmt-service` 模块
- 原因：班次配置数据在 device-mgmt 模块中
- 通过 Spring 的 `@Service` 注解自动注册为 Bean

### 4. 模块调用方式

#### 重构前（直接依赖实现）
```java
// efficiency-mgmt 模块直接依赖 device-mgmt 的实现类
private final ShiftConfigurationService shiftConfigurationService;
private final DeviceBaseInfoRepository deviceBaseInfoRepository;
```

#### 重构后（通过接口调用）
```java
// efficiency-mgmt 模块只依赖公共接口
private final ShiftQueryApi shiftQueryApi;

// 使用方式
ShiftInfoVO currentShift = shiftQueryApi.getFactoryCurrentShift(
    tenantId, factoryId, workshopId, null);
```

### 5. 依赖关系

#### 公共模块
- `common-api` - 只依赖 `common-domain` 和基础框架
- `common-domain` - 只依赖基础框架

#### 业务模块
- `efficiency-mgmt-service` - 依赖 `common-api`（通过接口调用）
- `device-mgmt-service` - 依赖 `common-api`（实现接口）

#### 依赖图
```
efficiency-mgmt-service
    └─> common-api (接口)
            └─> common-domain (VO)

device-mgmt-service
    └─> common-api (实现接口)
            └─> common-domain (VO)
```

## 优势

### 1. 模块解耦
- ✅ 各业务模块只依赖接口，不依赖具体实现
- ✅ 实现类可以放在任何模块中，不影响调用方
- ✅ 未来可以通过 RPC 方式提供实现，无需修改调用方代码

### 2. 可扩展性
- ✅ 公共模块可以扩展其他公共功能（如组织架构查询、权限验证等）
- ✅ 接口可以扩展新方法，不影响现有调用
- ✅ 支持多种实现方式（本地实现、RPC实现等）

### 3. 维护性
- ✅ 接口和实现分离，职责清晰
- ✅ 修改实现不影响调用方
- ✅ 便于单元测试（可以 Mock 接口）

## 注意事项

### 1. Spring Bean 注册
- 实现类必须使用 `@Service` 注解，确保 Spring 能够自动注册
- 接口和实现类必须在 Spring 扫描路径内

### 2. 依赖配置
- 调用方（如 efficiency-mgmt-service）需要在 pom.xml 中添加对 `common-api` 的依赖
- 实现方（如 device-mgmt-service）需要在 pom.xml 中添加对 `common-api` 的依赖

### 3. 循环依赖
- 避免公共模块依赖业务模块
- 公共模块应该是自包含的，只依赖基础框架
