# 定时任务失败与中断处理方案

**文档版本**：v1.0  
**创建日期**：2025-12-08  
**适用任务**：DeviceStateSummaryJob（设备状态汇总定时任务）

---

## 📋 问题分析

### 1. 失败场景

- **任务执行失败**：处理过程中抛出异常
- **任务超时**：XXL-Job 执行超时被强制终止
- **系统中断**：服务器重启、网络中断等
- **部分成功**：部分设备处理成功，部分失败

### 2. 影响分析

- **数据缺失**：部分班次未统计，导致历史数据不完整
- **数据重复**：重复执行可能产生重复数据
- **性能影响**：大量设备需要重新处理

---

## 🎯 解决方案设计

### 方案概述

采用**分片处理 + 检查点机制 + 幂等性保证 + 补偿任务**的组合方案，参考主流分布式任务调度框架（XXL-Job、Elastic-Job、Quartz）的最佳实践。

---

## 🔧 核心机制

### 1. 分片处理（Sharding）

**目的**：将大批量任务分成多个小批次，避免单次执行时间过长导致超时。

**实现方式**：
- 使用 XXL-Job 的分片参数（`shardingParam`）
- 或手动分批处理，每批处理固定数量的设备

**优势**：
- 降低单次执行时间
- 提高任务成功率
- 便于失败后重试

### 2. 检查点机制（Checkpoint）

**目的**：记录处理进度，失败后可以从断点恢复。

**实现方式**：
- 使用 Redis 存储检查点信息
- Key: `device_state_summary:checkpoint:{tenantId}:{factoryId}:{statisticsTimeSeconds}`
- Value: 已处理的设备ID列表（JSON）

**检查点数据结构**：
```json
{
  "tenantId": "xxx",
  "factoryId": "xxx",
  "statisticsTimeSeconds": 1234567890,
  "processedDeviceIds": ["device1", "device2", ...],
  "totalDeviceCount": 100,
  "processedCount": 50,
  "lastUpdateTime": 1234567890
}
```

### 3. 幂等性保证（Idempotency）

**目的**：确保重复执行不会产生重复数据。

**实现方式**：
1. **数据库唯一约束**：`device_state_summary` 表的 `(device_info_id, summary_date, shift_code)` 唯一约束
2. **状态检查**：处理前检查是否已统计且已确定（`is_finalized = 1`）
3. **更新而非插入**：如果已存在，则更新而非插入

**幂等性检查逻辑**：
```java
// 检查是否已统计过
DeviceStateSummaryDO existingSummary = findExistingSummary(...);
if (existingSummary != null && Boolean.TRUE.equals(existingSummary.getIsFinalized())) {
    // 已统计过，跳过
    return false;
}
```

### 4. 异常分类处理

**可重试异常**：
- 数据库连接异常
- 网络超时
- 临时性系统错误

**不可重试异常**：
- 数据格式错误
- 业务逻辑错误（如设备未配置班次）
- 数据不存在（如设备已删除）

**处理策略**：
- 可重试异常：记录到失败日志，等待下次重试
- 不可重试异常：记录到失败日志，标记为需要人工处理

### 5. 补偿任务（Compensation Job）

**目的**：定期扫描未处理的班次，进行补偿处理。

**实现方式**：
- 创建独立的补偿任务 `DeviceStateSummaryCompensationJob`
- 扫描 `device_state_summary` 表中 `is_finalized = 0` 的记录
- 或扫描最近 N 天内未统计的班次

**补偿任务执行频率**：
- 建议：每小时执行一次
- 或：每天凌晨执行一次，处理前一天的遗漏数据

### 6. 超时控制

**目的**：避免任务执行时间过长。

**实现方式**：
- XXL-Job 配置：设置任务超时时间（建议 30-60 分钟）
- 代码层面：设置单次处理的最大设备数量

**超时处理**：
- 记录已处理的设备到检查点
- 下次执行时从检查点恢复

## 📝 详细实现

### 1. 分片处理实现

#### 方案A：使用 XXL-Job 分片参数

```java
@XxlJob("deviceStateSummaryJob")
public void execute() {
    // 获取分片参数
    int shardIndex = XxlJobHelper.getShardingParam() != null 
        ? Integer.parseInt(XxlJobHelper.getShardingParam()) 
        : 0;
    int shardTotal = XxlJobHelper.getShardingTotal();
    
    // 按分片处理
    processByShard(shardIndex, shardTotal);
}
```

#### 方案B：手动分批处理（推荐）

```java
@XxlJob("deviceStateSummaryJob")
public void execute() {
    int batchSize = 50; // 每批处理50个设备
    int currentBatch = 0;
    
    while (true) {
        List<DeviceBaseInfoDO> batch = queryDevicesBatch(currentBatch, batchSize);
        if (batch.isEmpty()) {
            break;
        }
        
        processBatch(batch);
        currentBatch++;
        
        // 检查是否超时（预留5分钟）
        if (isTimeout(5 * 60 * 1000)) {
            saveCheckpoint(currentBatch);
            break;
        }
    }
}
```

### 2. 检查点机制实现

```java
/**
 * 保存检查点
 */
private void saveCheckpoint(String tenantId, String factoryId, 
                            long statisticsTimeSeconds, 
                            List<String> processedDeviceIds) {
    String key = String.format("device_state_summary:checkpoint:%s:%s:%d", 
                                tenantId, factoryId, statisticsTimeSeconds);
    
    CheckpointData checkpoint = new CheckpointData();
    checkpoint.setTenantId(tenantId);
    checkpoint.setFactoryId(factoryId);
    checkpoint.setStatisticsTimeSeconds(statisticsTimeSeconds);
    checkpoint.setProcessedDeviceIds(processedDeviceIds);
    checkpoint.setLastUpdateTime(System.currentTimeMillis() / 1000);
    
    redisClient.set(key, JsonUtils.toJsonString(checkpoint), 
                    24 * 3600, TimeUnit.SECONDS); // 24小时过期
}

/**
 * 加载检查点
 */
private CheckpointData loadCheckpoint(String tenantId, String factoryId, 
                                      long statisticsTimeSeconds) {
    String key = String.format("device_state_summary:checkpoint:%s:%s:%d", 
                                tenantId, factoryId, statisticsTimeSeconds);
    String value = redisClient.get(key);
    if (StringUtils.isBlank(value)) {
        return null;
    }
    return JsonUtils.parseObject(value, CheckpointData.class);
}

/**
 * 清除检查点
 */
private void clearCheckpoint(String tenantId, String factoryId, 
                            long statisticsTimeSeconds) {
    String key = String.format("device_state_summary:checkpoint:%s:%s:%d", 
                                tenantId, factoryId, statisticsTimeSeconds);
    redisClient.delete(key);
}
```

### 3. 从检查点恢复

```java
/**
 * 处理工厂设备（支持从检查点恢复）
 */
private void processFactoryWithCheckpoint(String tenantId, String factoryId,
                                         List<DeviceBaseInfoDO> devices,
                                         long statisticsTimeSeconds) {
    // 加载检查点
    CheckpointData checkpoint = loadCheckpoint(tenantId, factoryId, statisticsTimeSeconds);
    
    Set<String> processedDeviceIds = checkpoint != null 
        ? new HashSet<>(checkpoint.getProcessedDeviceIds())
        : new HashSet<>();
    
    // 过滤已处理的设备
    List<DeviceBaseInfoDO> remainingDevices = devices.stream()
        .filter(device -> !processedDeviceIds.contains(device.getId()))
        .collect(Collectors.toList());
    
    if (remainingDevices.isEmpty()) {
        XxlJobHelper.log("工厂 {} 所有设备已处理，清除检查点", factoryId);
        clearCheckpoint(tenantId, factoryId, statisticsTimeSeconds);
        return;
    }
    
    // 处理剩余设备
    List<String> newProcessedIds = new ArrayList<>();
    for (DeviceBaseInfoDO device : remainingDevices) {
        try {
            boolean processed = processDeviceShift(tenantId, device, statisticsTimeSeconds);
            if (processed) {
                newProcessedIds.add(device.getId());
                processedDeviceIds.add(device.getId());
            }
        } catch (Exception e) {
            log.error("处理设备失败: deviceId={}", device.getId(), e);
            // 继续处理下一个设备
        }
    }
    
    // 更新检查点
    if (!newProcessedIds.isEmpty()) {
        List<String> allProcessedIds = new ArrayList<>(processedDeviceIds);
        saveCheckpoint(tenantId, factoryId, statisticsTimeSeconds, allProcessedIds);
    }
    
    // 如果所有设备都处理完成，清除检查点
    if (processedDeviceIds.size() >= devices.size()) {
        clearCheckpoint(tenantId, factoryId, statisticsTimeSeconds);
    }
}
```

### 4. 补偿任务实现

```java
/**
 * 设备状态汇总补偿任务
 * 扫描未处理的班次，进行补偿处理
 */
@Slf4j
@Component
@RequiredArgsConstructor
public class DeviceStateSummaryCompensationJob {
    
    private final DeviceStateSummaryMapper stateSummaryMapper;
    private final DeviceStateSummaryJob summaryJob;
    
    @XxlJob("deviceStateSummaryCompensationJob")
    public void execute() {
        // 扫描最近7天内未确定的汇总记录
        LocalDate endDate = LocalDate.now();
        LocalDate startDate = endDate.minusDays(7);
        
        LambdaQueryWrapper<DeviceStateSummaryDO> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(DeviceStateSummaryDO::getIsFinalized, false)
               .between(DeviceStateSummaryDO::getSummaryDate, startDate, endDate)
               .orderByAsc(DeviceStateSummaryDO::getSummaryDate);
        
        List<DeviceStateSummaryDO> unprocessedSummaries = stateSummaryMapper.selectList(wrapper);
        
        XxlJobHelper.log("发现 {} 条未处理的汇总记录", unprocessedSummaries.size());
        
        int successCount = 0;
        int errorCount = 0;
        
        for (DeviceStateSummaryDO summary : unprocessedSummaries) {
            try {
                // 重新计算并更新
                summaryJob.recalculateSummary(summary);
                successCount++;
            } catch (Exception e) {
                errorCount++;
                log.error("补偿处理失败: summaryId={}", summary.getId(), e);
            }
        }
        
        XxlJobHelper.log("补偿任务完成: 成功={}, 失败={}", successCount, errorCount);
    }
}
```

## ⚙️ XXL-Job 配置建议

### 1. 任务配置

- **执行器**：选择支持分片的执行器
- **Cron表达式**：`0 */5 * * * ?`（每5分钟执行一次）
- **运行模式**：BEAN模式
- **JobHandler**：`deviceStateSummaryJob`
- **阻塞处理策略**：单机串行（避免并发执行）
- **任务超时时间**：30-60分钟
- **失败重试次数**：3次
- **失败重试间隔**：10分钟

### 2. 路由策略

- **推荐**：一致性HASH（保证同一工厂的设备由同一执行器处理）
- **备选**：轮询（负载均衡）

### 3. 分片配置（如果使用分片）

- **分片总数**：根据执行器数量设置（如：3个执行器，分片总数为3）
- **分片参数**：自动分配（0, 1, 2）

## 📊 监控与告警

### 1. 监控指标

- **任务执行成功率**：成功次数 / 总执行次数
- **平均处理时间**：每次执行的平均耗时
- **失败设备数量**：每次执行失败的设备数
- **补偿任务触发次数**：补偿任务执行的频率

### 2. 告警规则

- **任务连续失败**：连续3次执行失败，发送告警
- **失败率过高**：失败率 > 10%，发送告警
- **处理时间过长**：平均处理时间 > 30分钟，发送告警
- **补偿任务频繁触发**：补偿任务每天执行 > 5次，发送告警

### 3. 日志记录

- **详细日志**：记录每个设备的处理结果
- **错误日志**：记录异常堆栈信息
- **统计日志**：记录每次执行的统计信息

## 🔄 处理流程

### 正常执行流程

```
开始执行任务
    ↓
加载检查点（如果有）
    ↓
查询待处理设备（排除已处理设备）
    ↓
分批处理设备
    ├─ 处理设备1 → 更新检查点
    ├─ 处理设备2 → 更新检查点
    └─ ...
    ↓
所有设备处理完成
    ↓
清除检查点
    ↓
任务完成
```

### 失败恢复流程

```
任务执行失败/中断
    ↓
检查点已保存（记录已处理设备）
    ↓
下次执行时加载检查点
    ↓
跳过已处理的设备
    ↓
继续处理剩余设备
    ↓
更新检查点
    ↓
所有设备处理完成
    ↓
清除检查点
```

### 补偿任务流程

```
补偿任务触发
    ↓
扫描未处理的汇总记录
    ↓
遍历每条记录
    ├─ 重新计算汇总数据
    ├─ 更新 is_finalized = 1
    └─ 记录处理结果
    ↓
输出统计结果
```
