## 🎯 功能概述

### 1. 核心功能

`DeviceStateSummaryJob` 是一个基于 XXL-Job 的定时任务，用于在班次结束后自动统计设备状态数据并更新汇总表。

**主要功能**：
1. **自动触发**：班次结束后，延迟一段时间（可配置）自动启动统计
2. **状态统计**：统计班次内各状态的时长、占比、片段数等
3. **数据汇总**：将统计结果保存到 `device_state_summary` 表
4. **多设备支持**：支持批量处理所有设备
5. **多租户支持**：支持多租户环境
6. **按工厂分组处理**：先按租户分组，再按工厂分组，便于管理和监控

### 2. 业务价值

- **自动化**：无需人工干预，自动完成班次数据统计
- **准确性**：基于实际状态记录数据，确保统计准确
- **及时性**：班次结束后及时统计，支持实时查看历史数据
- **可追溯**：记录计算来源和时间，便于数据追溯
- **按工厂分组**：按工厂分组处理，提供工厂级别的统计和监控，便于问题定位和性能优化

## 🔄 处理流程

### 整体流程图

```
开始执行定时任务
    ↓
1. 读取配置（延迟时间）
    ↓
2. 计算统计时间点（当前时间 - 延迟时间）
    ↓
3. 查询所有设备（过滤未关联工厂的设备）
    ↓
4. 按租户分组，再按工厂分组
    ↓
5. 遍历每个工厂
    ├─ 5.1 遍历工厂内的每个设备
    │   ├─ 5.1.1 查询设备班次配置
    │   ├─ 5.1.2 计算已结束的班次
    │   ├─ 5.1.3 检查是否到统计时间
    │   ├─ 5.1.4 检查是否已统计过
    │   ├─ 5.1.5 查询班次内的状态记录
    │   ├─ 5.1.6 计算状态统计
    │   └─ 5.1.7 保存或更新汇总记录
    └─ 5.2 输出工厂处理结果（成功/跳过/失败）
    ↓
6. 输出总体统计结果（成功/跳过/失败）
    ↓
结束
```

### 详细处理逻辑

#### 步骤1：计算统计时间点

```java
long currentTimeSeconds = System.currentTimeMillis() / 1000;
long statisticsTimeSeconds = currentTimeSeconds - (delayMinutes * 60L);
```

**说明**：
- 统计时间点 = 当前时间 - 延迟时间
- 例如：当前时间 20:10，延迟5分钟，统计时间点为 20:05
- 统计时间点应该落在刚结束的班次内

#### 步骤2：查询所有设备并按工厂分组

```java
List<DeviceBaseInfoDO> allDevices = queryAllDevices();

// 先按租户分组，再按工厂分组
Map<String, Map<String, List<DeviceBaseInfoDO>>> devicesByTenantAndFactory = 
    allDevices.stream()
        .filter(device -> device.getOrgFactoryId() != null) // 过滤未关联工厂的设备
        .collect(Collectors.groupingBy(
            DeviceBaseInfoDO::getTenantUuid,
            Collectors.groupingBy(DeviceBaseInfoDO::getOrgFactoryId)
        ));
```

**说明**：
- 查询所有未删除的设备
- **过滤未关联工厂的设备**：只处理已关联工厂的设备，未关联工厂的设备会被跳过
- **按租户和工厂双重分组**：
  - 第一层：按租户分组（保证多租户数据隔离）
  - 第二层：在每个租户内，按工厂分组（便于按工厂处理和管理）
- **分组处理的优势**：
  - 提高处理效率：可以按工厂并行处理（如果后续需要）
  - 更好的日志记录：按工厂输出处理结果，便于监控和排查
  - 错误隔离：一个工厂出错不影响其他工厂的处理
  - 统计清晰：可以查看每个工厂的处理情况

#### 步骤3：按工厂处理设备

**处理流程**：
1. 遍历每个租户
2. 遍历租户内的每个工厂
3. 遍历工厂内的每个设备
4. 处理每个设备的班次统计
5. 输出工厂级别的处理结果

**工厂级别统计**：
- 每个工厂处理完成后，输出该工厂的统计结果（成功/跳过/失败数量）
- 便于监控和排查问题

#### 步骤4：处理单个设备

##### 4.1 查询班次配置

```java
Optional<ShiftConfigurationDO> configOpt = shiftConfigurationRepository
    .findActiveByDeviceAndTime(tenantId, deviceId, statisticsTimeSeconds * 1000L);
```

**说明**：
- 查询设备在统计时间点生效的班次配置
- 如果设备未配置班次，跳过该设备

##### 4.2 计算已结束的班次

```java
ShiftTimeRange previousShiftRange = calculatePreviousShiftRange(
    tenantId, factoryId, deviceId, config, statisticsTimeSeconds);
```

**说明**：
- 获取当前时间点的班次
- 计算前一个班次（刚结束的班次）
- 前一个班次的结束时间 = 当前班次的开始时间

**班次时间计算示例**：
- 假设当前时间：20:05
- 早班：08:00-20:00（已结束）
- 晚班：20:00-次日08:00（进行中）
- 前一个班次：早班（08:00-20:00）

##### 4.3 检查是否到统计时间

```java
long shiftEndTimeSeconds = previousShiftRange.getEndTs() / 1000;
long expectedStatisticsTime = shiftEndTimeSeconds + (delayMinutes * 60L);

if (statisticsTimeSeconds < expectedStatisticsTime) {
    // 班次还未到统计时间，跳过
    return false;
}
```

**说明**：
- 班次结束时间 + 延迟时间 = 期望的统计时间
- 如果统计时间点 < 期望的统计时间，说明还未到统计时间，跳过

**示例**：
- 班次结束时间：20:00
- 延迟时间：5分钟
- 期望统计时间：20:05
- 如果当前统计时间点为 20:03，则跳过（还未到统计时间）

##### 4.4 检查是否已统计过

```java
DeviceStateSummaryDO existingSummary = findExistingSummary(
    tenantId, deviceId, shiftDate, shiftCode);

if (existingSummary != null && Boolean.TRUE.equals(existingSummary.getIsFinalized())) {
    // 已经统计过且已确定，跳过
    return false;
}
```

**说明**：
- 检查是否已存在汇总记录
- 如果已存在且已确定（`is_finalized = true`），跳过（避免重复统计）
- 如果已存在但未确定，则更新记录

##### 4.5 查询班次内的状态记录

```java
List<DeviceStateTimelineDO> stateRecords = stateTimelineRepository.selectByRange(
    tenantId, deviceId, 
    previousShiftRange.getStartTs() / 1000, 
    previousShiftRange.getEndTs() / 1000);
```

**说明**：
- 查询班次时间范围内的所有状态记录
- 时间范围：班次开始时间 ~ 班次结束时间

##### 4.6 计算状态统计

```java
Map<String, StateStatistics> stateStats = calculateStateStatistics(
    stateRecords, shiftStartTs, shiftEndTs);
```

**统计内容**：
- 各状态的时长（秒）
- 各状态的占比（百分比）
- 各状态的片段数
- 缺失数据时长
- 数据完整度

**状态类型**：
- `WORKING`：加工中
- `STANDBY`：待机
- `FAULT`：故障
- `SHUTDOWN`：关机
- `UNKNOWN`：未知状态
- `MISSING`：缺失数据

**统计逻辑**：
1. 遍历所有状态记录
2. 计算每条记录在班次内的有效时长（取交集）
3. 按状态分组累加时长和片段数
4. 计算缺失数据时长 = 班次总时长 - 已记录时长
5. 计算各状态占比 = 状态时长 / 班次总时长

##### 4.7 保存或更新汇总记录

```java
saveOrUpdateSummary(tenantId, deviceId, shiftDate, shiftRange, stateStats);
```

**保存逻辑**：
1. 如果记录不存在，创建新记录
2. 如果记录已存在，更新记录
3. 设置 `is_finalized = true`（已确定）
4. 设置 `calculation_source = SCHEDULED`（定时任务）
5. 记录计算时间

## ⚙️ 配置说明

### 1. Apollo 配置

在 Apollo 配置中心添加以下配置：

```properties
# 班次结束后延迟多少分钟启动统计（默认5分钟）
shift.summary.delay-minutes=5
```

**配置说明**：
- **配置项**：`shift.summary.delay-minutes`
- **类型**：整数（分钟）
- **默认值**：5
- **建议值**：5-10分钟
- **说明**：延迟时间用于确保班次数据完整，避免在班次刚结束时统计导致数据不完整

### 2. XXL-Job 配置

在 XXL-Job 管理平台配置定时任务：

**任务配置**：
- **Job名称**：`deviceStateSummaryJob`
- **Job描述**：设备班次状态统计定时任务
- **执行器**：选择对应的执行器
- **Cron表达式**：`0 */5 * * * ?`（每5分钟执行一次）

**Cron表达式说明**：
- `0 */5 * * * ?`：每5分钟执行一次
- `0 */10 * * * ?`：每10分钟执行一次
- `0 0 * * * ?`：每小时执行一次

**建议配置**：
- 如果班次时长为8小时，延迟5分钟，建议每5-10分钟执行一次
- 如果班次时长为12小时，延迟5分钟，建议每10-15分钟执行一次
- 执行频率应该小于延迟时间，确保及时统计

**路由策略**：
- 建议使用 `轮询` 或 `一致性HASH`
- 如果有多台执行器，可以分散负载

**运行模式**：
- 建议使用 `BEAN模式`
- 任务类：`com.weili.iot_portal.task.devicemng.DeviceStateSummaryJob`

**超时时间**：
- 建议设置为 300秒（5分钟）
- 如果设备数量较多，可以适当增加

**失败重试**：
- 建议设置为 0（不重试）
- 因为定时任务会定期执行，失败的任务会在下次执行时重试

### 3. 常见问题

#### 问题1：任务未执行

**可能原因**：
- XXL-Job 任务未启动
- Cron表达式配置错误
- 执行器未注册

**解决方法**：
1. 检查 XXL-Job 任务状态
2. 验证 Cron表达式是否正确
3. 检查执行器是否正常注册

#### 问题2：设备未统计

**可能原因**：
- 设备未配置班次
- 班次未到统计时间
- 设备已统计过

**解决方法**：
1. 检查设备是否有班次配置（`device_shift_config` 表）
2. 检查班次结束时间 + 延迟时间是否已到
3. 检查是否已存在汇总记录（`device_state_summary` 表）

#### 问题3：统计数据不准确

**可能原因**：
- 状态记录数据不完整
- 班次时间计算错误
- 状态记录跨班次

**解决方法**：
1. 检查 `device_state_record` 表数据是否完整
2. 验证班次配置是否正确
3. 检查状态记录的时间范围是否在班次内

#### 问题4：任务执行超时

**可能原因**：
- 设备数量过多
- 数据库查询慢
- 网络延迟

**解决方法**：
1. 增加任务超时时间
2. 优化数据库查询（添加索引）
3. 分批处理设备（需要修改代码）

## 🔧 技术实现细节

### 1. 班次时间计算

#### 跨天班次处理

**示例**：晚班 20:00-次日08:00

```java
if (Boolean.TRUE.equals(shift.getCrossDay())) {
    // 跨天班次：开始时间是前一天
    shiftStart = shiftDate.minusDays(1).atTime(shiftStartTime);
} else {
    shiftStart = shiftDate.atTime(shiftStartTime);
}
```

**判断逻辑**：
- 如果结束时间 < 开始时间，则为跨天班次
- 例如：20:00 < 08:00（次日），为跨天班次

#### 前一个班次计算

```java
// 获取当前时间点的班次
ShiftTimeRange currentShift = shiftConfigurationService.calculateShiftRange(
    tenantId, factoryId, deviceId, statisticsTimeSeconds * 1000L);

// 前一个班次的结束时间 = 当前班次的开始时间
long previousShiftEndTs = currentShift.getStartTs();

// 根据班次配置计算前一个班次
ShiftTimeRange previousShift = calculateShiftRangeByEndTime(
    config, previousShiftEndTs);
```

### 2. 状态统计计算

#### 有效时长计算

```java
// 计算该记录在班次内的有效时长
long recordStartTs = record.getStartTs() != null ? record.getStartTs() : shiftStartTs;
long recordEndTs = record.getEndTs() != null ? record.getEndTs() : shiftEndTs;

// 取交集
long effectiveStart = Math.max(recordStartTs, shiftStartTs);
long effectiveEnd = Math.min(recordEndTs, shiftEndTs);
long duration = Math.max(0, effectiveEnd - effectiveStart);
```

**说明**：
- 状态记录可能跨班次
- 只统计班次内的有效时长
- 取状态记录和班次时间的交集

#### 缺失数据计算

```java
long totalRecordedDuration = statsMap.values().stream()
    .mapToLong(s -> s.durationSeconds)
    .sum();
long missingDataSeconds = Math.max(0, shiftDurationSeconds - totalRecordedDuration);
```

**说明**：
- 缺失数据 = 班次总时长 - 已记录时长
- 如果缺失数据 > 0，说明有数据缺失

### 3. 数据保存逻辑

#### 更新或插入

```java
DeviceStateSummaryDO summary = findExistingSummary(
    tenantId, deviceId, shiftDate, shiftCode);

if (summary == null) {
    // 创建新记录
    summary = new DeviceStateSummaryDO();
    summary.setId(IdWorker.getIdStr());
    // ... 设置字段
    stateSummaryMapper.insert(summary);
} else {
    // 更新已存在记录
    // ... 更新字段
    stateSummaryMapper.updateById(summary);
}
```

**说明**：
- 根据 `(device_info_id, summary_date, shift_code)` 唯一约束查找
- 如果不存在，创建新记录
- 如果已存在，更新记录

## 📈 性能优化建议

### 1. 数据库优化

#### 索引优化

确保以下索引存在：

```sql
-- device_state_record 表
CREATE INDEX idx_state_record_device ON device_state_record (device_info_id, start_ts);
CREATE INDEX idx_state_record_shift ON device_state_record (device_info_id, shift_date, shift_code);

-- device_state_summary 表
CREATE INDEX idx_state_summary_device ON device_state_summary (device_info_id, summary_date);
CREATE INDEX idx_state_summary_time_range ON device_state_summary (device_info_id, shift_start_ts, shift_end_ts);

-- device_shift_config 表
CREATE INDEX idx_shift_config_device ON device_shift_config (device_info_id, effective_start_ts);
CREATE INDEX idx_shift_config_active_effective ON device_shift_config (device_info_id, is_active, effective_start_ts DESC, effective_end_ts);
```

#### 查询优化

1. **批量查询**：如果设备数量较多，考虑分批查询
2. **缓存配置**：缓存班次配置，减少数据库查询
3. **异步处理**：考虑使用异步处理，提高响应速度

devices.parallelStream().forEach(device -> {
