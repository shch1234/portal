# 定时任务框架使用指南

**文档版本**：v1.0  
**创建日期**：2025-12-08  
**目的**：指导如何使用定时任务公共框架

---

## 📚 框架概述

定时任务公共框架提供了统一的异常处理、日志记录、统计收集等功能，大幅简化定时任务的开发。

### 核心类

| 类名 | 用途 | 适用场景 |
|------|------|---------|
| `BaseScheduledJob` | 基础任务 | 简单任务，不需要分批处理 |
| `BaseBatchJob<T>` | 分批处理任务 | 需要处理大量数据的任务 |
| `BaseCheckpointBatchJob<T>` | 支持检查点的分批任务 | 需要失败恢复的大批量任务 |
| `BaseCompensationJob<T>` | 补偿任务 | 扫描未处理数据并补偿的任务 |

### 工具类

| 类名 | 用途 |
|------|------|
| `CheckpointManager` | 检查点管理器（保存/加载/清除检查点） |
| `JobExecutionResult` | 任务执行结果（统计信息） |
| `ItemProcessResult` | 单项处理结果（成功/跳过/失败） |

## 🚀 快速开始

### 示例1：简单任务

适用于不需要分批处理的简单任务。

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class SimpleJob extends BaseScheduledJob {
    
    private final SomeService someService;
    
    @Override
    protected String getJobName() {
        return "简单任务";
    }
    
    @Override
    @XxlJob("simpleJob")
    public void execute() {
        super.execute();
    }
    
    @Override
    protected JobExecutionResult executeInternal() throws Exception {
        // 业务逻辑
        int successCount = someService.doSomething();
        return JobExecutionResult.of(successCount, 0, 0);
    }
}
```

**要点**：
- 继承 `BaseScheduledJob`
- 实现 `getJobName()` 返回任务名称
- 实现 `executeInternal()` 实现业务逻辑
- 在 `execute()` 方法上添加 `@XxlJob` 注解

### 示例2：分批处理任务

适用于需要处理大量数据的任务。

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class BatchProcessJob extends BaseBatchJob<DeviceBaseInfoDO> {
    
    private final DeviceBaseInfoMapper deviceBaseInfoMapper;
    private final SomeService someService;
    
    @Override
    protected String getJobName() {
        return "分批处理任务";
    }
    
    @Override
    @XxlJob("batchProcessJob")
    public void execute() {
        super.execute();
    }
    
    @Override
    protected List<DeviceBaseInfoDO> queryData() {
        // 查询待处理数据
        LambdaQueryWrapper<DeviceBaseInfoDO> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(DeviceBaseInfoDO::getDeleted, false);
        return deviceBaseInfoMapper.selectList(wrapper);
    }
    
    @Override
    protected ItemProcessResult processItem(DeviceBaseInfoDO device) {
        try {
            // 处理单个设备
            boolean success = someService.processDevice(device);
            return success ? ItemProcessResult.success() 
                          : ItemProcessResult.skipped("设备未配置");
        } catch (Exception e) {
            return ItemProcessResult.failed(e.getMessage());
        }
    }
    
    @Override
    protected String getItemId(DeviceBaseInfoDO item) {
        return item.getId();
    }
}
```

**要点**：
- 继承 `BaseBatchJob<T>`，T 是数据项类型
- 实现 `queryData()` 查询待处理数据
- 实现 `processItem()` 处理单个数据项
- 实现 `getItemId()` 返回数据项唯一标识

### 示例3：支持检查点的任务

适用于需要失败恢复的大批量任务。

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class CheckpointBatchJob extends BaseCheckpointBatchJob<DeviceBaseInfoDO> {
    
    private final DeviceBaseInfoMapper deviceBaseInfoMapper;
    private final CheckpointManager checkpointManager;
    private final SomeService someService;
    
    public CheckpointBatchJob(CheckpointManager checkpointManager) {
        super(checkpointManager);
    }
    
    @Override
    protected String getJobName() {
        return "支持检查点的任务";
    }
    
    @Override
    @XxlJob("checkpointBatchJob")
    public void execute() {
        super.execute();
    }
    
    @Override
    protected String buildCheckpointKey() {
        // 根据业务需求构建检查点Key
        // 例如：tenantId:factoryId:statisticsTimeSeconds
        long statisticsTimeSeconds = System.currentTimeMillis() / 1000 - 300;
        return "factory:statistics:" + statisticsTimeSeconds;
    }
    
    @Override
    protected List<DeviceBaseInfoDO> queryData() {
        return deviceBaseInfoMapper.selectList(new LambdaQueryWrapper<>());
    }
    
    @Override
    protected ItemProcessResult processItem(DeviceBaseInfoDO device) {
        // 处理逻辑
        return ItemProcessResult.success();
    }
    
    @Override
    protected String getItemId(DeviceBaseInfoDO item) {
        return item.getId();
    }
}
```

**要点**：
- 继承 `BaseCheckpointBatchJob<T>`
- 注入 `CheckpointManager` 并传递给父类
- 实现 `buildCheckpointKey()` 构建检查点Key
- 框架会自动处理检查点的保存、加载、清除

### 示例4：补偿任务

适用于扫描未处理数据并补偿的任务。

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class CompensationJob extends BaseCompensationJob<DeviceStateSummaryDO> {
    
    @Value("${shift.summary.compensation.days:7}")
    private int compensationDays;
    
    private final DeviceStateSummaryMapper stateSummaryMapper;
    private final SomeService someService;
    
    @Override
    protected String getJobName() {
        return "补偿任务";
    }
    
    @Override
    protected int getCompensationDays() {
        return compensationDays;
    }
    
    @Override
    @XxlJob("compensationJob")
    public void execute() {
        super.execute();
    }
    
    @Override
    protected List<DeviceStateSummaryDO> queryData() {
        // 查询未处理的数据
        LocalDate endDate = LocalDate.now();
        LocalDate startDate = endDate.minusDays(getCompensationDays());
        
        LambdaQueryWrapper<DeviceStateSummaryDO> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(DeviceStateSummaryDO::getIsFinalized, false)
               .between(DeviceStateSummaryDO::getSummaryDate, startDate, endDate);
        
        return stateSummaryMapper.selectList(wrapper);
    }
    
    @Override
    protected ItemProcessResult processItem(DeviceStateSummaryDO summary) {
        try {
            boolean success = someService.recalculateSummary(summary);
            return success ? ItemProcessResult.success() 
                          : ItemProcessResult.skipped("数据无效");
        } catch (Exception e) {
            return ItemProcessResult.failed(e.getMessage());
        }
    }
    
    @Override
    protected String getItemId(DeviceStateSummaryDO item) {
        return item.getId();
    }
}
```

**要点**：
- 继承 `BaseCompensationJob<T>`
- 实现 `getCompensationDays()` 返回扫描天数
- 框架会自动输出补偿任务的日志格式

## ⚙️ 配置说明

### Apollo 配置

```properties
# 分批处理配置
job.batch.size=50                    # 每批处理数量（默认50）

# 补偿任务配置（由子类配置）
shift.summary.compensation.days=7     # 扫描天数（示例）
```

### XXL-Job 配置

所有任务都需要在 XXL-Job 管理平台配置：

- **执行器**：选择对应的执行器
- **Cron表达式**：根据业务需求配置
- **运行模式**：BEAN模式
- **JobHandler**：对应任务的 `@XxlJob` 注解值
- **阻塞处理策略**：单机串行（避免并发执行）
- **任务超时时间**：30-60分钟
- **失败重试次数**：3次

## 🔧 高级用法

### 自定义超时时间

```java
@Override
protected long getTimeoutMs() {
    return 30 * 60 * 1000; // 30分钟
}
```

### 自定义检查点Key

```java
@Override
protected String buildCheckpointKey() {
    // 根据业务需求构建唯一Key
    String tenantId = getCurrentTenantId();
    String factoryId = getCurrentFactoryId();
    long timeSeconds = getStatisticsTimeSeconds();
    return String.format("%s:%s:%d", tenantId, factoryId, timeSeconds);
}
```

```java
    // 自定义统计输出格式

    // 额外的统计逻辑
}
```

## ✅ 最佳实践

### 1. 任务命名

- 使用清晰的任务名称，便于日志查看
- 补偿任务建议加上"补偿"后缀

### 2. 异常处理

- 在 `processItem()` 中捕获异常并返回 `ItemProcessResult.failed()`
- 框架会自动统计失败数量，不会中断整个任务

### 3. 检查点Key设计

- 检查点Key应该唯一标识本次处理任务
- 建议格式：`业务标识:时间戳` 或 `租户:工厂:时间戳`
- 避免使用可能重复的Key

### 4. 分批大小

- 根据数据量和处理时间调整 `batchSize`
- 建议范围：20-100
- 太小：频繁更新检查点，影响性能
- 太大：单批处理时间过长，容易超时

### 5. 超时控制

- 默认25分钟，预留5分钟给XXL-Job
- 根据实际处理速度调整
- 超时前会自动保存检查点

## 🐛 常见问题

### Q1: 如何知道任务是否使用了框架？

A: 查看任务类是否继承 `BaseScheduledJob` 或其子类。

### Q2: 检查点保存在哪里？

A: 保存在 Redis 中，Key 格式：`job:checkpoint:{jobName}:{checkpointKey}`，TTL 24小时。

### Q3: 如何清除检查点？

A: 框架会自动清除（所有数据处理完成后），也可以手动调用 `checkpointManager.clearCheckpoint()`。

### Q4: 任务失败后如何恢复？

A: 下次执行时会自动加载检查点，跳过已处理的数据，继续处理剩余数据。

### Q5: 如何查看任务执行统计？

A: 查看 XXL-Job 执行日志，框架会自动输出统计信息。
