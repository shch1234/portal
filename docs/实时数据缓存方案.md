# Portal 实时数据缓存方案（Redis）

> 适用范围：Portal 侧接收 ThingsBoard (TB) 下发的数据，将“实时数据”写入 Redis 供前端轮询；“业务数据”走原有落库流程。

## 1. 目标
- 实时数据写 Redis，前端 HTTP 轮询低延迟获取。
- 数据必须有过期时间；新值直接覆盖旧值（即使前端尚未消费）。
- 易扩展到多类实时数据（状态、指标、事件摘要、在线心跳等）。

## 2. 数据分流
- TB → Portal：按类别分流
  - **业务数据**：原有落库（DB/MyBatis）。
  - **实时数据**：直接写 Redis（覆盖写 + TTL），供前端轮询。
- 分类方式：eventType/topic 前缀；payload 标记（如 `realtime=true`）；或配置映射表（eventType → 业务/实时）。

## 3. Redis Key 设计
- 前缀：`rt:`（real-time），维度含租户/工厂/设备/类型。
- 当前状态（Hash）：`rt:state:{tenantId}:{factoryId}:{deviceId}`
- 指标/数值（Hash）：`rt:metric:{tenantId}:{factoryId}:{deviceId}`
- 最近事件摘要（Stream 或 capped List，可选）：`rt:event:{tenantId}:{factoryId}:{deviceId}`
- 在线心跳（String）：`rt:online:{tenantId}:{factoryId}:{deviceId}`

Hash 常用字段：
- 状态：`state`、`stateCode`、`updatedAt`(epoch ms)、`source`、`traceId`
- 指标：`metric.{name}`（如 `metric.oee`、`metric.temp`）、`updatedAt`、`source`、`traceId`

## 4. 过期与覆盖策略
- 状态/指标：Hash + TTL（配置化，建议 5~15 分钟）。
  - 写：`HSET` 覆盖 + `PEXPIRE`（每次写都刷新 TTL；若需强制过期则仅首次设 TTL）。
  - 满足“新值直接覆盖旧值”。
- 在线：`SETEX rt:online:... "1" ttlSeconds`，心跳续期。
- 事件摘要：Stream `XADD ... MAXLEN ~ N`，或 List `LPUSH` + `LTRIM`。

## 5. 幂等与乱序（可选）
- 默认：无序覆盖。
- 若需防乱序：比较 `incoming.updatedAt` 与存量 `updatedAt`，仅当更“新”时覆盖。

## 6. Portal 侧统一缓存服务（示意）
`RealTimeCacheService`：
- `saveDeviceState(...)`：key `rt:state:...`；`HSET` + `PEXPIRE`；字段含 `state/stateCode/updatedAt/source/traceId` 等。
- `saveMetrics(...)`：key `rt:metric:...`；`HSET` + `PEXPIRE`；字段 `metric.{name}` + 公共字段。
- `appendEvent(...)`（可选）：Stream `XADD ... MAXLEN ~ N` 或 List `LPUSH` + `LTRIM`。
- `touchOnline(...)`：`SETEX rt:online:... "1" ttlSeconds`。
- 配置：`rt.state.ttlMillis`、`rt.metric.ttlMillis`、`rt.online.ttlSeconds`、`rt.event.maxlen`。

## 7. 前端轮询接口（示意）
- `GET /api/rt/state?deviceId=...` → 读 `rt:state`，返回 `state/stateCode/updatedAt/source/traceId/isStale`
- `POST /api/rt/state/batch` → pipeline 读多设备
- `GET /api/rt/metrics?deviceId=...` → 读 `rt:metric`
- `GET /api/rt/online?deviceId=...` → `online=true/false`，可返回 `ttl`
- `isStale`：key 缺失或 `now - updatedAt` 超阈值（如 2×上报周期）。

## 8. 前端建议
- 轮询间隔：3~5s（高频），或 10s（低频）。
- 若 `isStale=true`：提示“数据可能延迟”，可触发后端补偿；UI 展示最后更新时间。

## 9. 权限与隔离
- key 含租户/工厂，接口层按租户/工厂鉴权过滤 deviceId。
- 大租户用 Redis Cluster，hash tag：`rt:{state}:{tenantId}:{factoryId}:{deviceId}` 保持同工厂同 slot。

## 10. 监控与告警
- 监控：key 数量、TTL 分布、过期率、写/读 QPS、p99。
- 告警：大量 stale、热点 key、写失败/超时。
- 指标：覆盖次数、幂等拒绝次数（若启用乱序保护）。

## 11. 过期与清理
- 配置化 TTL：`rt.state.ttlMillis`、`rt.metric.ttlMillis`、`rt.online.ttlSeconds`。
- 事件截断：Stream `MAXLEN` 或 List `LTRIM`。
- 批量清理：按前缀/租户/工厂扫描（谨慎生产扫描成本）。

## 12. 性能与扩展
- 写：batch/pipeline；读：批量接口 pipeline。
- 热点：本地短 TTL 缓存或 WS 推送（可选：写入时 `PUBLISH rt:channel:{tenantId}`）。
- 水平扩展：Redis Cluster；可按租户/工厂分片实例。

## 13. 落库与历史（可选）
- 实时数据仅存 Redis；历史分析落 DB 或 TSDB（Prometheus/ClickHouse）。
- 可订阅或定期下沉状态/指标到冷存储。

## 14. 异常与补偿
- 发现 stale/缺失：后台补偿（向上游重拉）；前端标记陈旧。
- 幂等保护（可选）：`updatedAt`/`seq` 防乱序覆盖。

## 15. 配置示例
- `rt.state.ttlMillis = 600000`（10 分钟）
- `rt.metric.ttlMillis = 600000`
- `rt.online.ttlSeconds = 60`（心跳 30s 上报一次）
- `rt.event.maxlen = 500`
- `rt.stale.thresholdMillis = 120000`（2 分钟未更新视为陈旧）
