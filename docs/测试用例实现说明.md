## 📝 测试编写规范

### 1. 测试类命名

- 测试类名：`被测试类名 + Test`
- 例如：`WebhookSecurityService` → `WebhookSecurityServiceTest`

### 2. 测试方法命名

- 使用 `@DisplayName` 注解提供中文描述
- 方法名使用驼峰命名，描述测试场景
- 例如：`testSignatureVerificationSuccess()`

### 3. 测试结构

```java
@Test
@DisplayName("TC-XXX-001: 测试场景描述")
void testScenario() {
    // Given - 准备测试数据
    // When - 执行测试
    // Then - 验证结果
}
```

### 4. Mock使用

- 使用 `@Mock` 注解Mock依赖
- 使用 `@InjectMocks` 注入被测试对象
- 使用 `@ExtendWith(MockitoExtension.class)` 启用Mockito

### 5. 断言使用

- 优先使用JUnit 5的断言方法
- 使用 `assertTrue()`, `assertEquals()`, `assertNotNull()` 等
- 使用 `assertThrows()` 测试异常场景

---

## ⚠️ 注意事项

### 1. 测试数据隔离

- 每个测试方法应该独立，不依赖其他测试的执行顺序
- 使用 `@BeforeEach` 初始化测试数据
- 使用 `@AfterEach` 清理测试数据（如需要）

### 2. Mock对象重置

- Mock对象在每次测试前会自动重置
- 不需要手动清理Mock状态

### 3. 时间相关测试

- 使用固定时间戳进行测试
- 避免使用 `System.currentTimeMillis()` 直接比较
- 使用时间范围断言（如 `assertTrue(time > start && time < end)`）

### 4. 异步测试

- 对于异步操作，使用 `CompletableFuture` 或 `CountDownLatch`
- 设置合理的超时时间
